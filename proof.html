Mathematisches Fundament

Kern-Theoreme & Systeminvarianten

Die Settlement-Engine implementiert ein Multi-Account Treuhand- und Gebührenabrechnungssystem. Jede Funktion deklariert exakte mathematische Kontrakte (req und ens), die zur Compile-Zeit zwingend bewiesen werden müssen.

Theorem 1: Exakte Wert-Erhaltung (Conservation of Total Wealth)
Bewiesen (Z3)

In jedem atomaren Abrechnungsschritt entspricht die Summe aller Guthaben nach dem Transfer zuzüglich der einbehaltenen Gebühr exakt der Summe der Ausgangsguthaben.

# Mathematische Behauptung in QAL: fn settle_total(s_before: Int, r_before: Int, amount: Int, fee: Int) -> Int req s_before >= amount && amount >= fee && fee >= 0 && r_before >= 0 ens r == s_before + r_before = let s_after = s_before - amount in let r_after = r_before + (amount - fee) in s_after + r_after + fee
Formale Z3-Reduktion: (s_before - amount) + (r_before + (amount - fee)) + fee ≡ s_before + r_before. Presburger lineare Arithmetik (QF_LIA) eliminiert amount und fee identisch und beweist die Invariante universell für alle ganzzahligen Eingabewerte.
Theorem 2: Striktes Überziehungsverbot & Gebührenschranke
Bewiesen (Z3)

Weder Sender noch Empfänger können ein negatives Guthaben annehmen. Die Transaktionsgebühr ist nach oben durch den Transferbetrag beschränkt.

ens r >= 0 && r == balance - amount # debit_balance: Saldo bleibt >= 0 ens r >= 0 && r <= amount # escrow_fee: Gebühr ist positiv und <= Betrag ens r >= 0 && r + fee == amount # escrow_net: Nettoauszahlung + Gebühr == Brutto
